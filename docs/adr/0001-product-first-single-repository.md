# ADR-0001：采用产品优先的单仓库

- 状态：Accepted
- 日期：2026-09-04

## 背景与约束

本仓库既要承载 16 周学习过程，也要在最终阶段作为求职作品。学习会覆盖 React、Python、Agent、RAG、MCP、评测和部署，但所有能力都围绕同一个 DevSupport Agent 演进。

## 考虑过的方案

1. 每周建立一个独立仓库。
2. 建立笔记优先的仓库，把项目放在深层子目录。
3. 建立产品优先的单仓库，把周记和实验作为辅助材料。

## 决定

选择方案 3：正式产品模块位于仓库一级目录；学习证据放在 `docs/`；不会被正式项目依赖的概念验证放在 `labs/`。

正式项目按需要逐步增加以下目录：

```text
frontend/
backend/
mcp_server/
knowledge_base/
evals/
```

## 正面影响

- 评审者进入仓库后可以优先理解和运行产品。
- 16 周历史仍可通过周记、规格、PR、ADR 和评测报告追溯。
- 所有阶段围绕同一套业务契约演进，避免产生互不相关的 Demo。
- `labs/` 与正式代码隔离，实验失败不会污染主项目。

## 代价与风险

- 仓库会同时包含 Python、TypeScript、文档和评测配置，需要分层 CI。
- 学习笔记可能膨胀，因此 README 只展示当前能力，详细过程保留在 `docs/weeks/`。
- 若 MCP Server 后续成为通用组件，可能需要再提取为独立仓库。

## 验证方法

- `main` 始终保持可运行。
- 陌生评审者能从根 README 找到运行方式、架构、指标和学习证据。
- `labs/` 不被正式产品模块 import。
- 每个阶段发布可复现的 Release，而不是创建新的仓库。

## 重新评估条件

当某个模块需要独立发布、独立版本策略或被多个项目复用时，再评估拆分仓库。
